# 多宠物 2D 互动前端设计与功能说明

## 1. 产品定位

这是一个可以直接操作的 2D 像素宠物空间。用户可以选择宠物和生活
场景，再通过点击、长按、移动与动作按钮和宠物互动。

设计目标不是做成管理后台或营销页面，而是让用户第一眼感到：

> 这是一个温暖、可玩、具有生命感的像素宠物小世界。

当前版本只做 2D 前端互动，不包含照片上传、3D、体素、AR、账号、
商城或成长数值系统。

## 2. 当前已经实现的功能

### 2.1 五只可切换宠物

| 名称 | 品种 | 主要身份特征 |
| --- | --- | --- |
| 豆包 | 红柴犬 | 红色被毛、奶油色脸胸、卷尾、青绿色项圈 |
| 金宝 | 金毛 | 金色长毛、垂耳、宽尾、蓝色项圈 |
| 雪团 | 比熊 | 白色蓬松卷毛、圆头、粉色项圈 |
| 可可 | 棕色泰迪 | 暖棕卷毛、长耳、黄色项圈 |
| 橘团 | 橘色异国短毛猫 | 橘色虎斑、扁圆脸、粗尾、绿色项圈 |

切换宠物后，页面会同步更新宠物图集、名称、品种、介绍、房间名称、
状态文字和所有可访问名称。当前场景与舞台位置保持不变。

### 2.2 六个可切换场景

| 场景 | 主要内容 | 环境表现 |
| --- | --- | --- |
| 客厅 | 木地板、地毯、窗户、书架、绿植 | 阳光与浮尘 |
| 花园 | 草地、花丛、木栅栏、树木、远山 | 树叶与蝴蝶 |
| 海滩 | 沙滩、海面、岛屿、遮阳伞、贝壳 | 海浪与云层 |
| 雪地小屋 | 木屋、雪景窗户、壁炉、毛毯 | 窗外雪花与火光 |
| 星光露营 | 月亮、松林、帐篷、营灯、草地 | 星光与萤火虫 |
| 屋顶 | 晚霞、城市天际线、护栏、花箱 | 城市灯光与远云 |

场景切换时会更新背景、选中状态、房间名称和场景播报。背景需要丰富，
但不能遮挡宠物、状态气泡或互动道具。

### 2.3 用户主动互动

| 操作 | 触发方式 | 用户看到的反馈 |
| --- | --- | --- |
| 开心 | 单击宠物 | 宠物做开心动作 |
| 抚摸 | 长按宠物 240ms 或拖动宠物 | 宠物进入放松、享受抚摸状态 |
| 左右移动 | 按住方向按钮或键盘方向键 | 宠物播放对应方向步态并真实移动 |
| 点击移动 | 点击或触摸场景空白处 | 宠物沿直线平滑走到目标点，斜向按主导轴选择方向动画 |
| 跳跃 | 点击“跳跃” | 宠物完成起跳与落地 |
| 喂食 | 点击“喂食” | 宠物低头进食并显示食盆 |
| 玩球 | 点击“玩球” | 宠物跳动并显示像素玩具球 |
| 梳毛 | 点击“梳毛” | 宠物放松并显示梳毛刷 |
| 洗澡 | 点击“洗澡” | 头顶出现竖直花洒，水流、泡泡和水花围绕宠物 |
| 跳舞 | 点击“跳舞” | 宠物开心摆动并显示节拍 |
| 拍照 | 点击“拍照” | 宠物摆姿势并显示拍照闪光 |
| 叫醒 | 点击叫醒按钮或产生有效输入 | 睡眠宠物恢复空闲状态 |

一次性动作结束后自动回到呼吸和眨眼状态。新的用户操作可以覆盖当前
动作，以最后一次输入为准。

### 2.4 自动生命状态

- 页面载入后，宠物处于呼吸和眨眼状态。
- 连续 12 秒没有输入，宠物进入等待状态。
- 连续 30 秒没有输入，宠物进入睡眠状态。
- 任意有效操作都会唤醒宠物并重新计算等待时间。

### 2.5 舞台移动和道具边界

- 宠物初始位置为舞台 `50 / 100`。
- 最左位置为 `8 / 100`，最右位置为 `92 / 100`。
- 左右动画使用独立图集，不通过镜像伪造方向。
- 食盆会根据宠物位置选择更安全的一侧。
- 玩具球在移动端受场景边界约束。
- 其他互动道具必须完整显示，不能依靠裁切隐藏越界问题。

## 3. 当前页面结构

### 顶部区域

- 产品名称与当前版本标识。
- 返回创建页入口。

### 宠物与场景选择区

- 当前宠物名称、品种和简短介绍。
- 五张宠物选择卡。
- 六张场景缩略卡。
- 当前场景文字反馈。

### 主要互动舞台

- 当前场景背景与环境动效。
- 可左右移动的像素宠物。
- 紧邻宠物的当前状态气泡。
- 根据动作出现的食盆、球、梳子、花洒淋浴、节拍和闪光。
- 当前舞台位置显示。

### 操作区

- 左右移动按钮。
- 跳跃、喂食、玩球、梳毛、洗澡、跳舞、拍照和叫醒按钮。
- 鼠标、触摸与键盘均可使用。

## 4. 新一轮前端视觉优化目标

### 4.1 视觉重点

1. 宠物始终是页面最强视觉焦点。
2. 场景应有空间层次和生活感，但不能抢过宠物。
3. 页面应像像素宠物游戏，而不是 SaaS 控制台。
4. 状态、宠物与操作按钮要形成清晰、紧凑的互动闭环。
5. 五只宠物和六个场景的选择要容易浏览，但不能形成拥挤的卡片墙。

### 4.2 桌面端

- 在 `1440×900` 内展示宠物选择、场景、舞台、状态和主要操作。
- 左侧信息区保持紧凑，右侧舞台占据主要面积。
- 减少无目的空白和重复边框，统一间距、字体、阴影和按钮层级。
- 操作按钮按“移动”和“互动”分组，按下反馈清楚。

### 4.3 移动端

- 在 `390×844` 下优先让用户看到宠物舞台和主要互动。
- 标题和说明应压缩，不应占据完整首屏。
- 宠物与场景选择器可以在自身内部横向滚动，但页面不能横向滚动。
- 主要按钮至少为 `44×44px`，文字清楚且容易触摸。
- 宠物移动到左右端点时，宠物、食盆和球都不能越界。

### 4.4 动效

- 保留现有像素精灵图动画。
- 可以优化状态切换、按钮按压和场景进入反馈。
- 新动效应克制、快速，不能压过宠物动作。
- `prefers-reduced-motion: reduce` 下必须关闭或明显简化新增动效。

## 5. 优化时必须保留的合同

- 不得替换、重绘或修改现有宠物与场景图片。
- 不得破坏五宠物、六场景和十六状态。
- 不得改变等待 12 秒、睡眠 30 秒和舞台 `8-92` 的规则。
- 不得改变宠物图集尺寸、网格和动画行映射。
- 不得删除鼠标、触摸、长按、键盘、焦点或减少动态效果支持。
- 不得引入 3D、WebGL、体素、AR 或大型前端依赖。
- 核心互动不得依赖远程字体或 CDN 图片；可选 DeepSeek 对话失败时必须
  自动回退本地回复，且密钥不得进入客户端或构建产物。
- 不得为了视觉效果破坏现有测试和资源路径。

## 6. 验收标准

- 五只宠物和六个场景都能正常切换。
- 所有原有互动和五个新增互动都能触发正确反馈。
- `1440×900`、`578×863`、`390×844` 均无页面级横向溢出。
- 移动端舞台高度不低于 `320px`，按钮高度不低于 `44px`。
- 宠物、状态气泡和互动道具不被错误裁切。
- 视觉层级明确，宠物身份没有变化。
- 键盘焦点顺序、状态播报和减少动态模式保持正常。
- 浏览器控制台无错误，测试、类型检查和生产构建全部通过。
