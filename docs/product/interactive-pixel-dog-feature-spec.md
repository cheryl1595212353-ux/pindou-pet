# 多宠物 2D 互动像素宠物功能规格

## 1. 文档信息

- 产品名称：拼豆宠物 · 2D 互动版
- 当前状态：五宠物、六场景、十六动作状态和七种心情均已实现
- 技术栈：React 19、TypeScript、Vite、CSS 精灵图动画
- 当前分支：`codex/pet-chat-emotions`
- 本轮验收基线：`c9ec739eaf00ee74dfc4d0548bec8ff0195c3eb4` 加当前工作树
- 本地入口：`http://127.0.0.1:5173/`

本产品只提供 2D 像素宠物与本地前端互动，不包含 3D、体素、OBJ、
WebGL、AR、账号、云端保存或照片上传。

## 2. 产品目标

用户打开页面后，可以选择五只身份清晰的像素宠物，把宠物放进六个
内容明显不同的场景，并通过点击、长按、移动、操作按钮和文字聊天
与它互动。

产品必须满足：

1. 每只宠物在全部动作中保持相同物种、毛色、脸型和配饰。
2. 场景不是简单换色，而是具有独立空间、前中后景和环境反馈。
3. 原有点击、抚摸、移动、跳跃、喂食、等待、睡眠和叫醒继续可用。
4. 玩球、梳毛、洗澡、跳舞和拍照都具有独立道具和文字反馈。
5. 桌面、平板宽度和移动端均无页面级横向溢出，控件可触摸、可聚焦。
6. 页面保持轻量，不引入 3D 或额外动画框架。
7. 宠物可在舞台中左右及前后移动，并可用滑块调整显示大小。
8. 阴影、食盆和玩具球随宠物的位置与尺寸保持视觉对位。
9. 用户可在像素对话框中聊天，并看到与回复一致的心情和颜文字反馈。

## 5. 产品状态与互动

产品共有十六个动作状态。九行动画图集负责角色动作，前后移动复用正面
空闲帧并增加轻微步态起伏，五个新互动复用相符动作行并叠加独立道具，
因此“十六个产品状态”与“九组角色动画”并不
冲突。

| 状态 | 触发方式 | 文字与视觉反馈 | 结束规则 |
| --- | --- | --- | --- |
| `idle` | 页面载入、叫醒或一次性动作结束 | 呼吸和眨眼 | 用户输入或进入等待 |
| `moving-left` | 按住左方向键或左按钮 | 向左步态和真实位移 | 松开后回到空闲 |
| `moving-right` | 按住右方向键或右按钮 | 向右步态和真实位移 | 松开后回到空闲 |
| `moving-forward` | 按住下方向键，或点击场景前方位置 | 靠近镜头、略微变大并轻微起伏 | 松开后回到空闲 |
| `moving-backward` | 按住上方向键，或点击场景后方位置 | 深入场景、略微变小并轻微起伏 | 松开后回到空闲 |
| `happy` | 单击宠物 | 开心、抬爪 | 播放一次后回到空闲 |
| `jumping` | 点击“跳跃” | 准备、起跳、落地 | 播放一次后回到空闲 |
| `sleeping` | 30 秒无输入 | 低伏闭眼睡觉 | 任意有效输入或叫醒 |
| `waiting` | 12 秒无输入 | 耐心等待 | 用户输入或继续至睡眠 |
| `feeding` | 点击“喂食” | 嘴部下方出现食盆并低头进食 | 播放一次后回到空闲 |
| `petting` | 长按 240ms 或拖动超过 7px | 放松、歪头并显示正在享受抚摸 | 松开后回到空闲 |
| `playing-ball` | 点击“玩球” | 跳跃动作和头部前方的像素玩具球 | 播放一次后回到空闲 |
| `grooming` | 点击“梳毛” | 放松动作和像素梳毛刷 | 播放一次后回到空闲 |
| `bathing` | 点击“洗澡” | 等待动作、头顶竖直花洒、水流和泡泡 | 播放一次后回到空闲 |
| `dancing` | 点击“跳舞” | 开心动作和节拍标记 | 播放一次后回到空闲 |
| `posing` | 点击“拍照” | 摆姿势动作和闪光 | 播放一次后回到空闲 |

每次有效输入都会重置等待和睡眠计时。新操作可以覆盖当前操作，以
最后一次用户输入为准。

## 6. 宠物聊天与心情

用户点击“和宠物聊天”后，舞台底部显示经典掌机式像素对话框。聊天优先
通过 Vite dev/preview 代理请求 DeepSeek；未配置密钥、请求失败或超时后
自动使用本地回复生成器，页面本身不依赖外部服务才能运行。

本地回退的意图按固定优先级识别：

1. 食物；
2. 玩耍；
3. 睡觉；
4. 夸奖；
5. 心情；
6. 场景；
7. 问候；
8. 未匹配时使用好奇回退。

DeepSeek 系统提示读取当前宠物固定档案、动作状态和场景，每只宠物保留
相互隔离的最近 12 条对话。五只宠物分别保持活泼、温柔、甜软、机灵和
慵懒的口吻。打开睡眠宠物的聊天会先生成“被叫醒”的本地即时反馈，再
通过现有 `wake` 事件回到空闲。

心情不占用精灵图动作行，固定为：

```text
calm  happy  excited  curious  shy  sleepy  content
```

对话框内显示中文心情标签和颜文字。每次回复后，宠物共享定位层周围显示
三枚错峰情绪符号和一枚颜文字气泡，约 `3.2s` 后消失。回复逐字显示，
完整句子只通过单独的 `aria-live="polite"` 区域播报一次。

输入长度上限为 80 个字符。空白内容不能发送，Enter 发送，Escape 关闭；
输入框中的方向键不得冒泡到房间移动。切换宠物时保留场景、位置和尺寸，
若聊天已打开则替换为新宠物欢迎语。

## 7. 移动、尺寸与道具边界

- 初始舞台位置：`{ x: 50, y: 50 }`
- 左右边界：`x = 8–92`
- 前后边界：`y = 20–80`
- 移动步长：`1.25`
- 移动刷新周期：`45ms`
- 左右方向使用独立图集行，不在运行时镜像同一行。
- 向前为 `ArrowDown`，增大 `y` 并靠近镜头；向后为 `ArrowUp`，
  减小 `y` 并深入场景。
- 前后方向使用正面图集帧和 CSS 像素级起伏，不宣称存在正背面行走素材。
- 每次按下立即移动一步，持续按住后按刷新周期连续移动。
- 点击或触摸场景空白处会把该点换算为舞台 `x`、`y` 坐标，宠物以相同的
  `45ms` 周期沿直线走向目标；斜向位移没有独立精灵图行，按主导轴选择
  左、右、前或后动画，不伪造斜向帧。
- 到达目标点后回到空闲；点击新位置立即改目标；点击对话框、按钮、
  滑块或宠物本身不触发场景移动；左右方向按钮、键盘和边界限制保持
  不变。
- 减少动态模式下点击场景直接落位，不播放连续位移动画。

尺寸滑块范围为 `70%–125%`，默认 `100%`，步长 `5%`。实际显示大小为
响应式基础尺寸、用户尺寸和景深比例的组合。景深比例由后景的 `0.90`
平滑增加到前景的 `1.08`。

食盆、玩具球和阴影与宠物共用二维舞台锚点：

- 五只宠物分别定义嘴部、头部前方和阴影宽度；
- 食盆位于进食动作嘴部下方，不再放在身体外侧；
- 玩球图集原始朝向为左，球默认位于头部左前方；
- 宠物接近左边界时，玩球动作和球同步镜像到右侧；
- 阴影宽度、透明度随用户尺寸和景深改变，跳跃和玩球时进一步收缩；
- 其他互动道具使用各自的 CSS 定位，并必须完整可见；
- 场景使用裁切边界，但不能用裁切掩盖道具越界；
- `390×844` 下最大尺寸、左右端点和前景端点均不得越出场景。

一次性互动动作的帧时长比上一版增加约 `45%`。移动、空闲、等待、
睡眠和抚摸的循环节奏不变；减少动画模式继续快速完成一次性动作。

## 8. 动画与资产合同

每只宠物使用相同目录：

```text
apps/web/public/pixel-dog/<pet-id>/
├── base.png
├── pet.json
└── spritesheet.webp
```

固定合同：

- `base.png`：`128×128` 透明 PNG；
- `spritesheet.webp`：`1536×1872` 透明无损 WebP；
- 网格：8 列 × 9 行；
- 单元格：`192×208`；
- 有效帧：57；
- 页面渲染：`image-rendering: pixelated`；
- `pet.json` 的 ID、路径、网格、动作行、帧数和循环属性必须与前端
  目录和 `DOG_CLIPS` 一致。

九行动作顺序固定为：

1. `idle`
2. `running-right`
3. `running-left`
4. `waving`
5. `jumping`
6. `failed`
7. `waiting`
8. `running`
9. `review`

场景资产位于：

```text
apps/web/public/pixel-dog/scenes/<scene-id>.webp
```

六张场景均为 `1600×900` 无损 WebP。

## 9. 页面结构和数据流

```text
宠物目录 / 场景目录
        ↓
选择宠物或场景
        ↓
更新图集、背景、标题、选中态和 aria-live

用户互动、聊天或尺寸输入
        ↓
动作 reducer、宠物聊天代理与本地回退模型，或更新二维位置与尺寸
        ↓
动作映射到九行动画 + 可选道具；聊天映射到回复 + 独立心情
        ↓
一次性动作完成后回到 idle
```

主要代码：

```text

├── PixelDogStudio.tsx
├── PixelDogStudio.test.tsx
├── petChatModel.ts
├── petChatModel.test.ts
├── petAssets.test.ts
├── petCatalog.ts
├── pixelDogModel.ts
├── pixelDogModel.test.ts
└── sceneCatalog.ts
```

## 10. 响应式规则

### 桌面端

- 左侧为说明和宠物、场景的弹出式选择入口；右侧为主要互动舞台。
- 宠物与场景选项默认收起，悬停或点击入口按钮才弹出面板，选择或
  Escape 后收起，不长期占用版面。
- 动作按钮、左右移动按钮和尺寸滑块组成舞台下方的独立浅色操作栏，
  不再嵌在深色房间框内。
- 舞台和操作栏在 `1440×900` 首屏内可见。
- 宠物始终是舞台最强视觉焦点。

### 中间和移动端

- 在 `578×863` 和 `390×844` 下改为单列。
- 宠物与场景选择入口并排一行，弹出的面板横向占满选择区，不造成
  页面级横向滚动。
- 操作栏中左右移动按钮与尺寸滑块同行，九个动作与聊天按钮组成
  四列网格行。
- 前后移动由键盘方向键和点击场景走位承担，不再提供向上、向下按钮。
- 不使用 CSS `order` 改变 DOM、视觉或读屏顺序。
- 每个按钮的可点击尺寸至少为 `44×44px`。
- 场景可视高度至少为 `320px`。
- 打开聊天时场景底部为对话框预留固定高度（桌面 `160px`、移动端
  `150px`），宠物整体随之上移，桌面场景扩展到至少 `620px`、移动端
  至少 `500px`，保证宠物头部和主体不被对话框遮挡。
- 状态、宠物、道具和食盆不得被场景错误裁切。

## 11. 无障碍与减少动画

- 互动房间可聚焦，并有“宠物名的场景名”可访问名称。
- 宠物、选择器入口、移动和动作按钮均有明确名称。
- 移动按钮使用“向左移动、向右移动”名称；前后移动保留键盘方向键。
- 宠物、场景入口按钮带 `aria-expanded` 和 `aria-haspopup="dialog"`，
  弹出面板为命名 `dialog`，Escape 关闭并把焦点还给入口按钮。
- 原生尺寸滑块使用“宠物大小”名称，并显示当前百分比。
- 当前互动只保留一个 `role="status"`。
- 场景切换使用独立的 `aria-live="polite"` 反馈。
- 对话框是有名称的非阻塞 `section`，输入和发送按钮随宠物名更新。
- 完整回复只在隐藏的礼貌播报区出现一次；逐字文字不重复进入无障碍树。
- 打开聊天后焦点进入输入框，Escape 或关闭按钮使焦点回到聊天按钮。
- 图集加载失败使用 `role="alert"`。
- 焦点轮廓清晰，所有可聚焦元素使用原生 DOM 顺序和 `tabIndex=0`。
- 选中卡片主文字与背景对比度为 `6.12:1`，次文字为 `5.52:1`。
- `prefers-reduced-motion: reduce` 下：
  - 场景环境动画和互动道具动画停止；
  - 宠物循环动画停在首帧；
  - 一次性动作快速完成；
  - 自动连续位移停止；
  - 点击场景移动直接落到目标点，不播放连续位移动画；
  - 花洒水流、泡泡和水花保持静态，不播放下落或闪烁动画；
  - 回复直接完整显示，情绪符号保持静态，不逐字播放或闪烁；
  - 状态、宠物、道具和全部按钮继续显示并可用。

## 12. 资源错误和清理

- 当前图集失败时显示“当前宠物名的动画图集没有加载成功”。
- 重新选择同一只宠物不会误清除该错误。
- 切换到另一只宠物时清除旧错误，并加载新图集。
- 组件卸载时清除帧计时、等待、睡眠、移动、长按、逐字和情绪计时器。
