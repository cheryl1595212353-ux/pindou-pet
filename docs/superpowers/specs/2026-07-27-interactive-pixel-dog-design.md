# 2D 互动像素狗产品设计

日期：2026-07-27  
分支：`codex/interactive-pixel-dog`  
宠物：豆包，一只红柴犬

## 1. 决策

本产品只做 2D 像素宠物，不再包含 3D 重建、Quad、体素网格或 OBJ。

采用“真实参考照 → 锁定身份的像素主形象 → 多状态透明精灵图集 → 浏览器互动状态机”的路线。现有 3D 文件保留但不修改、不导入首页，也不进入新产品运行时。

## 2. 目标与非目标

### 目标

- 由生成的真实红柴犬照片建立唯一身份参考。
- 生成接近 `128×128` 可见尺寸、约 32 色、清晰硬边的像素主形象。
- 输出二值透明背景的动画图集和宠物配置。
- 提供静止呼吸与眨眼、等待、睡觉、左右移动、跳跃、点击开心、抚摸反馈和喂食反馈。
- 在现有 React/Vite 应用首页交付可运行的互动产品。
- 完成自动校验、组件测试、构建检查和最终动作联系表视觉检查。

### 非目标

- 不支持 3D 视角旋转、模型导出或 AR 三维放置。
- 不训练新的生成模型。
- 首版不提供用户上传、账号、云端保存或多宠物管理。
- 不删除旧 3D 实现；只让新首页不再依赖它。

## 3. 方案比较

### A. 单张 PNG 加 CSS 变形

最快，但只能整体缩放、晃动和位移，眨眼、睡觉、喂食及身份一致的姿态变化不够真实。

### B. 多帧精灵图集加小型状态机（采用）

每个行为由独立的像素帧表示，视觉清晰、运行轻量、测试边界明确，也最符合本产品的复古像素气质。

### C. 2D 骨骼绑定

动作可复用，但需要拆分头、腿、尾巴等部件并进行绑定。对于一张照片生成的首版产品，工程复杂度和视觉修复成本过高。

## 4. 视觉与内容设计

### 视觉 thesis

一个温暖、克制的像素宠物房间：纸张与木色的安静表面、掌机游戏般的清晰像素、少量青绿色状态强调。

### 内容计划

1. 顶栏只保留产品名和当前宠物名。
2. 主工作区以豆包和可移动的房间舞台为唯一视觉中心。
3. 下方动作栏提供跳跃、喂食和唤醒；移动同时支持按钮与方向键。
4. 一行状态文字说明豆包当前正在呼吸、等待、睡觉或回应互动。

### 互动 thesis

- 空闲时以细微呼吸和眨眼建立生命感。
- 行为切换使用短促、可读的姿态变化，不添加粒子、光效或装饰噪声。
- 左右移动改变宠物在舞台中的真实位置；点击、长按抚摸和喂食都得到明确状态反馈。

页面是操作界面而不是营销落地页：不使用卡片矩阵、长文案或装饰性仪表盘。

## 5. 资产合同

### 身份锁

所有视觉子任务都必须同时参考：

- 真实红柴犬参考照；
- 已选定的像素主形象；
- 对应动作的布局引导图。

不可改变的身份特征：

- 红色被毛；
- 奶油色口鼻、脸颊、胸腹；
- 小白袜；
- 深棕色眼睛和黑鼻；
- 完整卷尾；
- 简单青绿色项圈；
- 紧凑、友好的成年柴犬比例。

### 图像格式

- 可见主体按约 `128×128` 像素视觉密度设计。
- 动画单元格为 `192×208`，为跳跃、抬爪和卷尾留出安全边距。
- 图集为 8 列 × 9 行，即 `1536×1872`。
- 最终格式为无损透明 WebP，并保留透明 PNG 验证产物。
- 透明区域的 RGB 必须归零；未使用单元格必须完全透明。
- 页面使用 `image-rendering: pixelated`，不做平滑插值。

### 状态映射

| 产品状态 | 图集行 | 行为 |
| --- | --- | --- |
| `idle` | `idle` | 呼吸、眨眼、轻微头部起伏 |
| `moving-right` | `running-right` | 向右移动 |
| `moving-left` | `running-left` | 向左移动 |
| `happy` | `waving` | 点击后友好抬爪和开心回应 |
| `jumping` | `jumping` | 原地起跳后回到空闲 |
| `sleeping` | `failed` | 无泪光和符号的闭眼低伏姿态 |
| `waiting` | `waiting` | 耐心等待用户输入 |
| `feeding` | `running` | 食盆出现时的专注轻摆反馈 |
| `petting` | `review` | 长按抚摸时歪头、眨眼和尾部回应 |

生成端仍保持固定九行合同；产品层只负责语义映射。

## 6. 交互规则

- 页面加载后进入 `idle`。
- 连续 12 秒无输入进入 `waiting`。
- 连续 30 秒无输入进入 `sleeping`。
- 任意键盘、按钮或指针输入立即唤醒。
- 单击宠物进入一次性 `happy`，播放完成后返回 `idle`。
- 在宠物上长按或拖动进入 `petting`，松开后返回 `idle`。
- 按住左右方向键或舞台按钮进入对应移动状态，并在舞台边界内更新位置；松开返回 `idle`。
- 点击跳跃进入一次性 `jumping`，完成后返回 `idle`。
- 点击喂食后显示食盆并进入一次性 `feeding`，完成后返回 `idle`。
- `prefers-reduced-motion` 开启时停用自动位移动画，仅显示每个状态的首帧和即时状态文字。

## 7. 前端边界

新增独立功能目录：

```text
apps/web/src/app/pixel-dog/
  PixelDogStudio.tsx
  PixelDogStudio.test.tsx
  pixelDogModel.ts
  pixelDogModel.test.ts
```

职责：

- `pixelDogModel.ts`：纯状态、动作事件、计时阈值、图集行和帧配置。
- `PixelDogStudio.tsx`：舞台、精灵渲染、指针/键盘交互、计时器和无障碍反馈。
- `router.tsx`：首页静态导入改为 `PixelDogStudio`；不再把 Three/WebGL 依赖拉入首页。
- `styles.css`：只追加 `.pixel-dog-*` 命名空间样式和必要关键帧。

运行时不新增状态机或动画依赖。React reducer、计时器和 CSS background-position 足够完成首版。

资产放在：

```text
apps/web/public/pixel-dog/doubao/
  real-reference.png
  spritesheet.webp
  pet.json
```

## 8. 数据流与故障处理

```text
用户事件
  → reducer 计算产品状态
  → 状态映射到图集行与帧时长
  → CSS background-position 显示当前帧
  → 一次性动作完成后回到 idle
```

- 图集加载失败时显示可访问的错误提示，不用空白舞台伪装成功。
- 连续快速操作以最新用户输入为准，并重置等待/睡眠计时器。
- 浏览器失焦或组件卸载时清理移动循环与计时器。
- 图片技术校验通过但身份漂移时仍判定失败；最终视觉检查优先于自动 PASS。

## 9. 测试与验收

### 自动测试

- reducer 覆盖全部九个产品状态和返回空闲规则。
- 假计时器验证 `idle → waiting → sleeping`。
- 测试点击、长按、左右移动、跳跃、喂食和唤醒。
- 测试舞台位置不会越界。
- 测试当前状态通过 `aria-live` 和 `data-state` 暴露。
- 运行 Web 单测、TypeScript 类型检查和生产构建。

### 视觉验收

- 主形象仍能辨认为真实参考中的同一只红柴犬。
- 九行动作中脸、被毛、白袜、卷尾和青绿色项圈保持一致。
- 空闲帧确实有呼吸或眨眼，不是六张静态复制。
- 左右移动方向和步态正确。
- 无背景残留、白底、阴影、光晕、裁切、跨格或尺寸跳变。
- 等待、睡觉、开心、抚摸和喂食在页面上下文中可读。
