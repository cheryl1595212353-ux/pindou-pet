# 虚拟宠物 Phase 1A：2.5D 方块像素风修订设计规格

状态：用户已确认视觉方向，待书面规格批准

日期：2026-07-17

修订范围：只替换 Phase 1A 的角色美术方向；已通过的身份卡、合成猫三视图、
本地文件校验、哈希证据和用户门禁继续复用。

## 1. 修订原因

上一版把用户所说的“像素感”错误实现为实体拼豆造型，生成结果出现圆形豆粒、
中央豆孔和塑料材质。用户已明确拒绝该解释，并确认目标是：

> 看起来有轻微立体感、但本质仍是游戏像素画的 2.5D 方块像素虚拟宠物。

因此，旧的三张拼豆候选全部作废，不进行抠图或风格补救。它们继续保存在原
`var/phase-1a/synthetic-cat-01/` 运行目录中，作为错误路线和三次调用上限的证据。

## 2. 方案比较与选定方向

### 2.1 方案 A：经典平面 2D 像素精灵

优点是最接近传统游戏 sprite，轮廓清楚，后续动画简单；缺点是体积感较弱，
可能无法满足用户所说的“立体图像”。

### 2.2 方案 B：2.5D 屏幕像素精灵（选定）

角色仍由朝向屏幕的方形像素块组成，通过有限色阶、块面高光和阴影表达脸部、
身体和尾巴的体积。像素本身不挤出成圆豆、立方体或实体模型。该方案兼顾游戏
像素感、身份辨识度和轻微立体效果，是本轮正式路线。

### 2.3 方案 C：体素／方块雕塑

立体感最强，但容易变成 Minecraft 式立方体、积木或三维模型，偏离用户要求的
“图像是像素画”。本轮不采用。

## 3. 不变输入与证据边界

- 继续使用已通过独立审查的同一只短毛三花猫身份卡。
- 继续使用已通过的 `FRONT`、`CAT_LEFT_FRONT_45`、
  `CAT_RIGHT_FRONT_45` 三张摄影参考图。
- 猫自身左眼橘斑、猫自身右耳及相邻头顶黑斑、背部橘黑斑块、橘黑环纹深色尾尖
  的解剖方向定义不变。
- Codex 和子 agent 仍只用于开发期人工编排，不进入 Web/API 运行时。
- 不使用用户 API Key，不新增 Provider adapter，不宣称产品延迟、成本或真实宠物
  生成能力已经验证。
- 运行媒体、实际提示词、审查记录和 manifest 仍只写入被 Git 忽略的 `var/`。

## 4. 新运行目录与历史隔离

新的像素风验证使用独立运行根目录：

```text
var/phase-1a/synthetic-cat-01-pixel-v2/
```

身份卡、参考提示词、通过的母版和三张裁切图复制到新目录，并保留原哈希。不得
覆盖旧拼豆运行中的提示词、原始调用图片和失败记录。新旧两条路线不能共用
`candidate-01.png` 等同名证据文件。

## 5. 角色构图

- 输出一个居中的完整静态角色，耳朵、爪、身体和尾巴均不得裁切。
- 脸朝向用户；身体向画面右侧约 20°；尾巴位于画面右侧。
- 保持自然猫比例，可轻微可爱化，但不得改成另一只猫或夸张玩偶头身比。
- 不增加表情剧情、项圈、衣服、道具、文字、标志或场景。

## 6. 2.5D 方块像素视觉合同

### 6.1 必须出现

- 清晰、朝向屏幕的方形像素块和阶梯状轮廓；缩放后仍能看出像素网格节奏。
- 所有像素对齐到同一张二维栅格，格子之间没有实体间隙、孔洞或独立透视旋转。
- 用少量连贯色块表达白色身体、绿色眼睛、橘黑脸部斑纹、背部斑块和尾巴环纹。
- 用有限色阶的整片块面高光与阴影表达轻微体积；不为每一个像素绘制凸起、倒角
  或独立材质，也不使用连续摄影渐变冒充像素画。
- 眼睛、鼻子、耳缘和尾尖允许使用较小像素组，但不得退化成毛发级噪声。
- 最终角色必须是具有非空可见内容和真实 alpha 通道的 PNG。

### 6.2 明确禁止

- 圆形拼豆、豆孔、塑料管、熔豆、底板、实体拼豆颗粒或手工作品摄影感。
- 挤出的立方体、乐高积木、Minecraft／voxel 雕塑和可任意旋转的三维模型。
- 平滑矢量插画、真实毛发、摄影纹理、连续柔化边缘和抗锯齿毛边。
- 棋盘格、白色、纯色或阴影背景被画进 RGB 图片；模拟透明不算真实 alpha。
- 漂浮像素、随机抖动、过密噪点、错误肢体、交换花纹或被裁切的尾巴。

## 7. 候选差异

首轮最多三个候选，身份、构图和透明要求完全相同，只允许以下一个维度变化：

1. `candidate-01`：较细像素尺度，身份和花纹保真优先；
2. `candidate-02`：中等像素尺度，块面明暗和 2.5D 体积稍强；
3. `candidate-03`：中等像素尺度，轮廓略圆润可爱，但不改变自然比例。

不得出现第四种姿势、配饰、背景或美术材质。每次生成调用都计入三次上限，
机械失败不能用未记录的额外调用替换。

## 8. 透明背景和一次校正

优先要求生成工具直接返回真实透明 PNG。若某个候选在身份和像素风上通过、但
仅背景不透明，用户可以先选中该候选，再把“只移除背景并建立真实 alpha，其他
像素、颜色、轮廓、构图和身份均不变”作为唯一一轮校正。

这种图片只能以“待背景修复的风格预览”展示，不能标记为 alpha 合格候选，也不能
直接复制为最终角色。

背景修复后的图片必须重新通过 alpha、像素风和身份检查。修复导致像素被重画、
边缘柔化、花纹漂移或仍无真实 alpha 时，记录 `STOP_REVISE_STYLE`，不得做第二轮
修复。背景校正不是新增第四个造型候选。

## 9. 预览与像素保持

- `character-hd.png`：最终透明高清像素角色。
- `preview-58.png`：将完整角色等比放入 58×58 透明画布，仅使用最近邻缩放。
- `preview-464.png`：把 `preview-58.png` 以 8 倍最近邻放大到 464×464。

整个预览流程不使用双线性／双三次平滑，不锐化、不重新生成，也不加入真实拼豆
色板或豆数统计。预览标记改为 `PIXEL_ART_VISUAL_PROXY`；它用于验证低分辨率轮廓
和主要花纹，不自动宣称已经完成可动画的分层 sprite sheet。

## 10. 用户门禁与验收

候选只有同时满足以下条件才可提交用户选择：

- 一眼可认出与三张参考图属于同一只猫；
- 标志脸部斑纹、绿色眼睛、白色主色、背部斑块和尾巴环纹保持正确；
- 姿势符合固定构图，完整且无多余肢体；
- 视觉主体由方形屏幕像素组成，具有轻微 2.5D 明暗；
- 不含任何圆豆、豆孔、塑料拼豆、体素雕塑或真实毛发效果；
- PNG 具有真实 alpha，或者用户明确选择后仅剩一次背景校正；
- 58×58 和 464×464 预览仍能辨认轮廓与主要花纹。

最终 PASS 仍只能由用户给出。子 agent、自测或“整体不错”不能替代用户选择。
用户批准最终结果时记录 `VISUAL_PROTOTYPE_PASS`；三个候选均被拒绝或唯一校正失败
时记录 `STOP_REVISE_STYLE`。

## 11. 实施影响

本修订只授权后续实施计划修改以下内容：

- 把已提交的拼豆候选提示词模板改成 2.5D 方块像素模板；
- 更新对应的模板合同测试和产品声明字符串；
- 新建隔离的 pixel-v2 私有运行目录并复制已通过的身份与参考证据；
- 由子 agent 生成最多三个新候选、执行独立风格审查和用户门禁；
- 用户选择后生成最近邻预览和最终 manifest。

不授权重做 Phase 0、重新生成三视图、增加 Web/API 路由、引入付费 API、制作动画、
拆层、骨骼、三维模型或实体拼豆图纸。

## 12. 阶段出口

`VISUAL_PROTOTYPE_PASS` 只证明合成猫的 2.5D 方块像素视觉路线值得继续，不证明
真实宠物、网页自动生成、性能或 Provider 可行性已经通过。

`STOP_REVISE_STYLE` 表示继续调整像素尺度、轮廓或身份保持方式；不得退回实体拼豆
解释，也不得在没有新书面规格的情况下进入动画和产品化。
