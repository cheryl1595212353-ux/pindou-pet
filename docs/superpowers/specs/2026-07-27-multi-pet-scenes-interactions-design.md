# 多宠物、多场景互动像素宠物扩展设计

日期：2026-07-27  
分支：`codex/interactive-pixel-dog`  
状态：用户已确认，后续规格与资产取舍由 Codex 代为确认

## 1. 决策

在现有 2D 互动像素宠物产品上继续扩展，不引入 3D、WebGL、账号、云端保存或用户上传。

采用以下组合方案：

1. 每只宠物拥有独立、完整的九行动画图集，继续使用现有 `8 × 9` 图集合约。
2. 场景使用独立像素背景图，加少量 CSS 前景和环境动画。
3. 新互动作为独立产品状态，通过已有动作行、专属道具和场景反馈组合实现，不扩充图集行数。
4. 宠物、场景和互动全部由静态目录配置驱动，React 状态机负责运行时切换。

该方案优先保证宠物身份清晰、场景可辨认、互动反馈明确，同时避免把五只宠物的图集扩展为十四行以上。

## 2. 可验收目标

交付完成时必须同时满足：

- 五只可切换宠物：红柴犬、金毛、比熊、棕色泰迪、橘色异国短毛猫。
- 六个可切换场景，超过“至少五个”的要求。
- 保留现有点击、抚摸、左右移动、跳跃、喂食、等待、睡眠和叫醒。
- 新增五个可触发互动：玩球、梳毛、洗澡、跳舞、拍照。
- 每次宠物、场景或互动切换都有即时、可访问的文字反馈。
- 移动端食盆不会在左右边界被裁切。
- DOM、键盘焦点和视觉顺序保持一致。
- 桌面端和 `390 × 844` 移动端无横向滚动，舞台、宠物、状态和操作可用。
- 单元测试、类型检查和生产构建通过。

## 4. 动画资产合同

所有宠物继续使用现有合同：

- 图集尺寸：`1536 × 1872`
- 网格：8 列 × 9 行
- 单元格：`192 × 208`
- 格式：透明无损 WebP
- 主形象：`128 × 128` 透明 PNG
- 页面渲染：`image-rendering: pixelated`

九行动作依次为：

1. `idle`
2. `running-right`
3. `running-left`
4. `waving`
5. `jumping`
6. `failed`
7. `waiting`
8. `running`
9. `review`

每只宠物必须完成图集结构验证、动作联系表检查和逐行动画预览检查。身份漂移、错误物种、裁切、背景残留、尺寸跳变或错误移动方向都阻止资产进入应用。

## 6. 新增互动

新增状态仍引用九行动画图集中的现有动作行，但每项拥有独立道具、状态文字和完成规则。

| 产品状态 | 用户操作 | 动作行 | 专属视觉反馈 | 结束规则 |
| --- | --- | --- | --- | --- |
| `playing-ball` | 点击“玩球” | `jumping` | 球从宠物前方弹起并滚动 | 一次播放后回到空闲 |
| `grooming` | 点击“梳毛” | `review` | 梳子经过背部，宠物放松回应 | 一次播放后回到空闲 |
| `bathing` | 点击“洗澡” | `waiting` | 浴盆、泡泡和结束时的轻微甩水 | 一次播放后回到空闲 |
| `dancing` | 点击“跳舞” | `waving` | 宠物有节奏摆动，舞台出现短暂节拍标记 | 一次播放后回到空闲 |
| `posing` | 点击“拍照” | `waving` | 宠物摆姿势，出现倒计时和一次闪光 | 一次播放后回到空闲 |

道具必须靠近或包围宠物，不能成为与角色无关的全屏装饰。状态反馈使用当前宠物名称，例如“雪团正在玩球”。

## 7. 前端结构

保留现有功能目录，新增两个纯数据模块：

```text
apps/web/src/app/pixel-dog/
  PixelDogStudio.tsx
  PixelDogStudio.test.tsx
  pixelDogModel.ts
  pixelDogModel.test.ts
  petCatalog.ts
  sceneCatalog.ts
```

职责：

- `petCatalog.ts`：五只宠物的名称、品种、资产路径和视觉说明。
- `sceneCatalog.ts`：六个场景的名称、背景路径和主题 ID。
- `pixelDogModel.ts`：十四个产品状态、事件、图集行、帧时长和边界规则。
- `PixelDogStudio.tsx`：宠物与场景选择、互动调度、精灵渲染、道具层和无障碍反馈。
- `styles.css`：场景布局、选择器、道具、响应式行为和减少动态效果。

组件名与既有 `.pixel-dog-*` CSS 命名空间暂时保留，避免本轮为内部命名进行无价值的全文件改名。

## 8. 页面布局

### 桌面端

- 左侧是紧凑控制区：当前宠物、宠物选择、场景选择和简短操作说明。
- 右侧是主要舞台：状态条、场景、宠物、道具和操作栏。
- 宠物始终是舞台中的最强视觉焦点。

### 移动端

- 控制区压缩为标题、横向宠物选择和横向场景选择。
- 控制区之后立即出现舞台，避免长文案占据首屏。
- 操作按钮按 DOM 顺序自然换行，不用 CSS `order` 改变视觉顺序。
- 方向按钮和互动按钮均保持至少 `44px` 点击高度。

页面不新增营销段落、成长数值、货币、任务或卡片仪表盘。

## 9. 状态与数据流

```text
选择宠物或场景
  → 更新目录 ID
  → 重置当前一次性互动
  → 切换图集或背景
  → aria-live 报告结果

触发互动
  → reducer 进入产品状态
  → 状态映射到图集动作行
  → 道具层根据状态出现
  → 动作完成后返回 idle
```

切换宠物时保留舞台位置和当前场景，但立即回到 `idle`，防止旧宠物的一次性动作延续到新宠物。

图集加载失败只影响当前宠物，页面显示当前宠物名称对应的错误提示，用户仍可切换其他宠物。

## 10. 边界与无障碍修复

### 食盆边界

食盆跟随宠物，但根据舞台位置选择侧边：

- 宠物位于舞台左侧或中央时，食盆显示在右侧。
- 宠物超过约 `70%` 时，食盆切换到左侧。

食盆最终位置仍由场景边界约束，必须在 `8%` 和 `92%` 两个移动端端点都完整可见。

### 顺序一致性

- 不再使用 `.pixel-dog-room { order: -1; }`。
- 不再通过 `order` 交换动作按钮和移动按钮。
- DOM 顺序、视觉顺序、键盘 Tab 顺序和读屏顺序保持一致。

### 动态效果

`prefers-reduced-motion` 开启时：

- 宠物循环动画停在首帧。
- 一次性动作快速完成。
- 自动连续位移停止。
- 场景环境动画和闪光动画停止。
- 状态文字、切换和全部按钮仍可使用。
