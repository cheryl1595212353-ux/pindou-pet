# 像素宠物本地聊天与情绪反馈设计

## 1. 状态

- 日期：2026-07-28
- 方案：本地关键词回复，不接入外部大模型
- 范围：现有五只宠物、六个场景和默认互动首页
- 不包含：账号、云端聊天记录、后端 API、模型密钥、语音和新精灵图

## 2. 目标

用户可以打开一个类似经典宝可梦游戏的像素对话框，向当前宠物输入文字并
获得符合宠物性格、当前动作和场景的本地回复。每次回复都带有明确的心情，
对话框内部显示心情名称和颜文字，宠物周围短暂闪烁爱心、音符、问号、汗滴
或星星等符号。

聊天必须在离线状态下稳定工作，且不能破坏现有移动、尺寸、场景、等待、
睡眠及互动动作。

## 3. 方案比较

### 方案 A：确定性本地意图规则（采用）

- 根据关键词识别问候、食物、玩耍、夸奖、睡觉、心情和场景七类意图。
- 回复参考宠物、动作与场景，结果可测试、无费用、无网络依赖。
- 缺点是不能回答开放知识问题，但符合第一版陪伴互动的边界。

### 方案 B：浏览器内随机语料库

- 每类意图随机选择多条回复，表面变化更多。
- 随机行为会降低测试稳定性，仍不能获得真正的语义理解。

### 方案 C：外部大模型

- 可以自由对话，但需要后端、密钥、费用、限流和内容安全。
- 超出当前无需 API 的产品合同，不进入本轮范围。

## 4. 视觉与内容方向

- **视觉主张：** 深色双线像素边框像一台掌机的对话窗口，奶油色文字面板
  与现有舞台配色一致，情绪只用一个强调色和少量像素符号表达。
- **内容计划：** 舞台仍是主视觉；对话框在舞台底部出现，依次呈现宠物名与
  心情、用户上一句话、宠物回复、输入与发送操作。
- **互动主张：**
  1. 对话框用短促的像素阶梯式入场，不改变页面布局；
  2. 宠物回复逐字出现，但读屏一次获得完整句子；
  3. 宠物周围的三个情绪符号错峰闪烁后自动消失，心情标签继续保留。

不新增卡片网格、弹窗遮罩或新的主导航。聊天按钮加入现有动作操作区，
对话框只在用户主动打开后显示。

## 5. 本地聊天模型

新增独立的 `petChatModel.ts`，不把文案匹配逻辑继续塞入页面组件。

```ts
type PetMood =
  | "calm"
  | "happy"
  | "excited"
  | "curious"
  | "shy"
  | "sleepy"
  | "content";

interface PetReply {
  intent: ChatIntent;
  mood: PetMood;
  text: string;
}
```

意图按明确优先级匹配，避免一句话同时命中时出现不稳定结果：

1. 食物；
2. 玩耍；
3. 睡觉；
4. 夸奖；
5. 心情；
6. 场景；
7. 问候；
8. 未匹配时进入好奇回应。

空白输入不会提交。输入比较忽略英文大小写和首尾空格。回复不得执行用户
文本、插入 HTML 或调用网络。

## 6. 五只宠物的性格

五只宠物共用意图识别和心情语义，但具有不同的稳定口吻：

| 宠物 | 性格 | 回复风格 |
| --- | --- | --- |
| 豆包 | 活泼 | 直接、热情，喜欢立刻行动 |
| 金宝 | 温柔 | 耐心、陪伴感强 |
| 雪团 | 甜软 | 轻快，喜欢贴近用户 |
| 可可 | 机灵 | 好奇，常提出小问题 |
| 橘团 | 慵懒 | 句子较慢，偏爱舒服和零食 |

切换宠物后，对话内容切换为新宠物的欢迎语；场景、位置和尺寸继续保留。

## 7. 动作与场景上下文

- 宠物正在睡觉时打开或发送消息，回复先表达刚被叫醒，再由现有 `wake`
  事件回到空闲状态。
- 正在进食、玩球、洗澡、梳毛、跳舞或拍照时，回复可以优先提及当前动作。
- 场景意图必须在回复中使用当前场景显示名称。
- 发送消息属于有效输入，会重置等待与睡眠计时。
- 聊天心情与精灵动作是两个独立状态，避免为每种心情新增不存在的动画行。

## 8. 对话框行为

- “聊天”按钮打开对话框，再次点击或使用关闭按钮可以关闭。
- 打开时显示当前宠物欢迎语，并把焦点移动到文本输入框。
- 表单包含最多 80 个字符的单行文本输入和不小于 `44×44px` 的发送按钮。
- `Enter` 发送，空白输入的发送按钮禁用；`Escape` 关闭对话框。
- 输入框内使用方向键只移动光标，不触发宠物移动。
- 页面不持久化聊天记录；界面只保留上一条用户消息和当前宠物回复。
- 切换宠物时若对话框已打开，立即替换为新宠物欢迎语并保持可输入。

## 9. 情绪反馈

心情展示数据由模型统一提供：

| 心情 | 标签 | 对话框颜文字 | 舞台符号 |
| --- | --- | --- | --- |
| calm | 平静 | `(･ω･)` | `·` |
| happy | 开心 | `(ᵔᴥᵔ)` | `♥` |
| excited | 兴奋 | `٩(ˊᗜˋ*)و` | `✦` |
| curious | 好奇 | `( •̀ ω •́ )?` | `?` |
| shy | 害羞 | `(⁄ ⁄•⁄ω⁄•⁄ ⁄)` | `♡` |
| sleepy | 困倦 | `(－ω－) zzZ` | `Zz` |
| content | 满足 | `(๑´ڡ｀๑)` | `♪` |

舞台反馈绑定宠物的共享定位和缩放层，因此移动、景深和尺寸变化时仍跟随
宠物。每次回复触发约三秒的错峰闪烁；之后符号消失，但对话框中的心情仍
表示当前状态。`prefers-reduced-motion: reduce` 下不逐字播放、不闪烁，
直接显示完整回复和静态心情符号。

## 10. 无障碍与错误边界

- 对话框使用有名称的 `section`，不是阻塞页面的 modal。
- 完整宠物回复通过单独的 `aria-live="polite"` 状态一次播报。
- 逐字文本标记为 `aria-hidden="true"`，避免重复朗读。
- 所有按钮、输入和心情均有可访问名称或可见标签。
- 聊天打开时不会移除舞台和原操作，关闭后焦点回到聊天按钮。
- 本地模型没有网络错误；若输入没有匹配，使用好奇回应而不是报错。
- 现有图集加载错误继续优先显示，不被情绪符号遮挡。

## 11. 验收标准

1. 用户可以打开、关闭对话框，输入文字并使用按钮或 Enter 发送。
2. 七类关键词和未匹配输入产生正确意图、心情和非空本地回复。
3. 五只宠物对同一输入具有不同口吻；切换宠物显示新的欢迎语。
4. 回复参考当前睡眠/互动动作和当前场景，发送后宠物被唤醒。
5. 对话框内显示心情标签及颜文字，宠物周围短暂显示错峰情绪符号。
6. 输入框的方向键不移动宠物，Escape 可关闭，焦点行为与读屏播报正确。
7. 聊天不改变二维位置、用户尺寸、场景和既有互动结果。
8. 减少动态模式直接显示完整回复，并停止逐字与闪烁动画。
9. 自动测试、类型检查、生产构建和 `git diff --check` 通过。
10. 在 `1440×900`、`578×863`、`390×844` 真实浏览器中检查布局、输入、
    五宠物切换、情绪反馈、触摸尺寸、横向溢出和控制台。
