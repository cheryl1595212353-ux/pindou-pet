# 拼豆宠物 Minecraft 风格 3D 方块猫 Demo 设计规格

日期：2026-07-19  
状态：待书面批准

## 1. 背景与目标

当前可用 Demo 已支持五只内置测试猫、十五张正面／侧面／俯视参考图、浏览器内 2D 像素化、点击跳动和 PNG 下载。用户已确认下一版需要将主要互动对象改为类似《我的世界》角色的真正 3D 方块猫，而不是带立体阴影的 2D 图片。

本阶段目标是在现有 Web Demo 中交付一个无需后端、无需 API 密钥、可立即试用的 3D 方块猫：五只测试猫共用一套方块骨架，分别使用确定性的像素外观配置；用户可以旋转、缩放、切换固定视角，并看到待机与点击动画。

这是对原 2D／准 2D MVP 边界的明确扩展。它只验证固定模板 3D 互动方向，不宣称已经实现照片到任意 3D 宠物的自动重建。

## 2. 已选方案与取舍

采用“程序化方块骨架 + 低分辨率像素贴图”方案。Three.js 负责 3D 渲染，React Three Fiber 负责将场景和 React 状态连接起来；实现阶段可使用 Drei 提供的相机控制辅助组件。依赖版本必须与当前 React 19、TypeScript 和 Vite 工程兼容，并由 lockfile 冻结。

未选择以下路线：

- 预制 GLB／Blender 模型：初始视觉完成度高，但每次修改骨架、枢轴或花纹都需要重新处理二进制模型，当前迭代较慢。
- 三视图自动体素重建：能产生差异化几何，但当前输入一致性和轮廓质量不足，容易生成破碎或畸形体素，不适合作为快速体验版。

## 3. 范围

### 3.1 本阶段包含

- 一套由方块部件组成的猫骨架；
- 五套可明显区分的猫咪像素外观；
- 鼠标和触摸拖动旋转；
- 滚轮和双指缩放；
- 正面、侧面、俯视三个相机预设；
- 呼吸、眨眼、摇尾和点击跳跃／爱心；
- WebGL 错误边界、响应式尺寸和减少动态效果支持；
- 单元测试、组件测试和浏览器交互验证。

### 3.2 本阶段不包含

- 从照片自动生成 3D 几何或像素贴图；
- 每只猫独立的胖瘦、长短毛或骨架比例；
- GLB 导入、Blender 制作流程或骨骼蒙皮；
- 键盘行走、地图探索、碰撞、寻路或自由漫游；
- AR、原生 App、小程序或服务端模型；
- 3D 模型导出；
- 上传真实照片的运行时入口。

## 4. 页面与组件架构

首页继续使用“左侧选择与说明、右侧主要互动舞台”的现有布局。左侧保留五只测试猫的缩略图，隐藏真实照片上传和 2D 像素颗粒、颜色层次、背景容差、PNG 下载控制。正面／侧面／俯视按钮改为相机预设，而不是切换 2D 输入图。

主要模块边界如下：

### `PixelPetStudio`

负责页面布局、当前猫咪 ID、相机预设请求和用户可见状态。它不创建 Three.js 对象，也不实现动画插值。

### `VoxelCatScene`

负责 Canvas、相机、灯光、地面、阴影、OrbitControls、尺寸变化、WebGL 错误边界以及相机预设过渡。它接收当前外观和互动事件，不保存猫咪业务数据。

### `VoxelCatModel`

负责方块猫的层级结构和可动画枢轴。它只接收经过验证的 `CatAppearance`，并向上暴露点击事件。

### `catAppearances`

保存五套纯数据外观配置和默认三花配置。该模块不依赖 React 或 Three.js 场景状态，可独立校验和测试。

### `useCatAnimation`

把时间、减少动态效果设置和 `IDLE`／`JUMPING` 状态转换为根节点高度、身体呼吸、眼睛开合和尾巴各段旋转值。它不直接处理指针或相机。

现有十五张 AI 测试猫照片继续用于左侧缩略图和人工制作外观时的视觉参考，但不参与运行时识别、纹理提取或网络请求。

## 5. 方块骨架

所有可见结构均由低多边形方块构成，不使用平滑毛发或有机曲面。模型根节点位于四爪中心的地面投影处，竖直方向为 Y 轴。

层级至少包含：

- `root`：整体跳跃和朝向；
- `bodyPivot/body`：身体与轻微呼吸；
- `headPivot/head`：头部；
- `muzzle`：口鼻方块；
- `leftEar/rightEar`：两只方块耳朵；
- `leftEye/rightEye`：可切换睁眼／闭眼像素面；
- 四个 `legPivot/leg`：独立腿部方块；
- `tailRoot/tailMiddle/tailTip`：两到三节尾巴，保证摇动有清楚的折线感。

首版五只猫使用相同部件尺寸、位置和枢轴。长毛、英短胖瘦及其他体型差异只通过外观表达，后续如需要再引入多个几何模板。

## 6. 像素外观

每个 `CatAppearance` 至少包含：

- `id`、显示名称和说明；
- 主毛色、次毛色、深色、胸口／爪色、眼睛色和鼻子色；
- 面部、身体两侧、背部、腿部和尾巴的低分辨率花纹矩阵；
- 纹理生成所需的固定分辨率和调色板索引。

运行时从这些纯数据确定性生成 CanvasTexture 或 DataTexture。纹理必须使用 nearest-neighbor 过滤，禁用 mipmap 导致的模糊效果，并使用适合方块表面的离散色块。相同配置在每次加载时必须产生相同纹理。

五套外观分别表现：

- 小满：黑、橙、白三花，绿色眼睛；
- 橘子：橘色虎斑，琥珀眼睛；
- 墨墨：黑白燕尾服、白胸白爪，黄色眼睛；
- 银豆：银灰虎斑，铜色眼睛；
- 奶盖：奶油色身体、深色面罩耳朵和尾巴，蓝色眼睛。

外观配置缺失、重复 ID、非法颜色或花纹尺寸错误时，开发期校验必须失败；运行时错误边界回退到默认三花外观并显示非阻塞提示。

## 7. 场景与相机

场景使用暖色工作室背景、简单地面、环境光和一盏主方向光。方块猫和地面接收／投射阴影，但不增加高成本后处理。

OrbitControls 行为：

- 水平方向允许完整 360°旋转；
- 垂直方向限制在地面以上，不能进入地板或翻到模型下方；
- 禁用平移，避免猫离开舞台中心；
- 最近和最远距离固定，不能穿入模型或缩小到不可见；
- 鼠标拖动和触摸单指旋转；滚轮和双指缩放。

三个预设相机目标分别为正面、左侧面和正上方俯视。触发后在约 350ms 内插值到目标位置和注视点；减少动态效果启用时立即切换。用户在预设过渡结束后仍可自由旋转。

## 8. 互动与动画

动画只有两个互斥主状态：

- `IDLE`：轻微身体呼吸、周期眨眼和连续慢速摇尾；
- `JUMPING`：根节点在 650ms 内完成一次起跳、到达约一个身体高度 20% 的顶点并落地，爱心同步上浮；落地后回到 `IDLE`。

点击和拖动必须区分：指针按下到抬起的总移动距离不超过 5 个 CSS 像素时才触发跳跃，旋转拖动不能误触。点击反馈在下一渲染帧开始，目标延迟小于 200ms。跳跃期间的新点击不叠加第二套动画；旋转和缩放仍然可用。

正常动态模式下，每 4.5 秒触发一次 120ms 眨眼，测试使用注入时钟而不等待真实时间。减少动态效果启用时停止呼吸、自动摇尾和自动眨眼，相机预设立即切换；点击仍提供一个不引发大位移的短暂爱心反馈。

## 9. 数据流

1. 首页默认选择小满。
2. `PixelPetStudio` 根据猫咪 ID 取得并验证 `CatAppearance`。
3. `VoxelCatScene` 保持同一个 WebGL 场景，只把新外观传给 `VoxelCatModel`。
4. 纹理生成器按配置创建或复用确定性像素纹理；切猫不重建 Canvas、相机或控制器。
5. 每帧由 `useCatAnimation` 输出动画值，模型组件应用到对应枢轴。
6. 相机按钮只发送预设请求，不修改模型外观或动画状态。

不产生网络上传、后端任务、API 密钥或本地用户照片。

## 10. 错误与降级

- WebGL 初始化失败时，在舞台区域显示“当前浏览器不支持 3D”，保留猫咪选择区，不伪装成成功的 2D 结果。
- 外观配置无效时使用默认三花配置，并显示非阻塞状态提示。
- 纹理生成或渲染异常由局部错误边界捕获，不使整个路由白屏。
- 页面尺寸变化时更新相机宽高比和渲染器尺寸，不创建第二个渲染循环。
- 组件卸载时释放动态纹理、材质、几何体、控制器和动画帧引用。

## 11. 测试策略

### 单元测试

- 五个唯一猫咪 ID 和完整调色板；
- 所有花纹矩阵尺寸及索引合法；
- 骨架必需部件和枢轴名称完整；
- 纹理生成确定性、最近邻和无平滑配置；
- `IDLE → JUMPING → IDLE` 状态以及重复点击不叠加；
- 减少动态效果分支；
- 非法外观回退默认三花。

### React 组件测试

- 默认选择小满；
- 五只猫可切换且传递正确外观；
- 三个按钮发送正确相机预设；
- 上传和 2D 调节控件不再出现在默认 3D 页面；
- WebGL 错误提示可访问。

### 浏览器验证

- 真实 WebGL 场景可见且控制台无错误；
- 水平旋转、缩放和三个相机预设工作；
- 五套外观视觉上可明显区分；
- 点击出现一次跳跃和爱心，拖动不误触跳跃；
- 页面调整大小后仍完整显示；
- 在开发机常用桌面视口稳定达到至少 30fps。

## 12. 验收标准

本阶段只有在以下条件全部满足时才算完成：

1. 首页主要互动对象为真实 WebGL 3D 方块猫，而不是 2D 图片或伪 3D 阴影。
2. 五只测试猫共用固定骨架，但颜色、关键花纹和眼睛明显不同。
3. 用户可以拖动 360°观察、缩放，并使用正面／侧面／俯视预设。
4. 正常动态模式下，呼吸、眨眼、摇尾和点击跳跃／爱心可见，点击响应小于 200ms；减少动态效果模式使用本规格定义的降级反馈。
5. 拖动不会误触点击跳跃，跳跃不会叠加。
6. WebGL 不可用和非法外观均有明确降级路径。
7. 所有新增测试、现有 Web 测试、类型检查和生产构建通过。
8. 浏览器控制台无错误，桌面目标达到至少 30fps。

## 13. 后续方向

本阶段通过后，可按优先级另行设计：多套胖瘦／长短毛几何模板、从三视图半自动生成像素贴图、键盘行走、场景互动、GLB 导出，以及 AR 场景放置。任何一项都不属于本规格的隐含交付内容。
