# 像素宠物本地聊天与情绪反馈实施计划

## 成功条件

- 经典像素对话框、本地关键词回复、五宠物口吻、动作与场景上下文、独立
  心情状态和对话框内外情绪反馈均有代码与测试证据；
- 聊天与既有移动、尺寸、场景、动作、等待和睡眠兼容；
- 产品规格、README、需求登记和新的浏览器 QA 反映最终行为；
- Web 测试、类型检查、构建、差异检查及三个目标视口的真实浏览器验收通过；
- 只创建本地提交，不推送或合并 GitHub。

## 步骤

1. **建立本地聊天模型**
   - 先编写失败测试，覆盖七类意图、未匹配输入、动作和场景上下文。
   - 定义七种心情、显示数据与五只宠物口吻。
   - 验证：模型测试覆盖每只宠物且回复完全确定。

2. **建立对话组件状态**
   - 增加打开、关闭、输入、上一条用户消息、回复、心情和短暂情绪爆发状态。
   - 增加逐字显示 hook，并为减少动态模式提供立即完成路径。
   - 验证：组件测试覆盖按钮、Enter、Escape、空白输入、焦点和播报。

3. **接入现有宠物状态机**
   - 发送和打开聊天均作为有效输入；睡眠宠物被唤醒。
   - 回复接收发送前的宠物状态和当前场景。
   - 输入框方向键不冒泡到舞台移动。
   - 验证：聊天前后位置、尺寸、场景和既有互动保持不变。

4. **完成像素对话框和情绪视觉**
   - 在舞台底部加入掌机式对话框、心情标签、颜文字和输入表单。
   - 在共享宠物定位层加入三个错峰舞台符号及短暂颜文字气泡。
   - 增加对话框入场、逐字光标和情绪闪烁；减少动态模式静态显示。
   - 验证：语义选择器和样式状态测试覆盖主要视觉合同。

5. **更新产品与协作文档**
   - 更新 README、功能规格、AGENTS 状态数量与交互说明。
   - 新增 `REQ-20260728-02`，完成后记录自动和浏览器证据。

6. **完整自动验证**
   - 运行相关测试，再运行完整 Web 测试、类型检查和生产构建。
   - 运行 `git diff --check` 并检查最终差异。

7. **真实浏览器验收**
   - 在桌面、`578×863`、`390×844` 检查打开/关闭、输入、Enter、Escape、
     五宠物口吻、睡眠唤醒、场景回复、情绪动画、减少动态、触摸尺寸、
     横向溢出和控制台。
   - 将测量和行为证据写入新的 QA JSON。

8. **本地提交**
   - 确认暂存区只包含本目标文件。
   - 创建本地功能提交，不 push、不创建 PR、不合并。
